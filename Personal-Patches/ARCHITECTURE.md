# Personal lyrics architecture

Full and Lyrics-only share one personal Java runtime, Braccato renderer, provider catalog and native settings. Full supplies its collection infrastructure. The add-on packages only isolated personal classes and uses compile-only official contracts; it requires official default Music patches and rejects a second lyrics integration.

LyricsEntryCoordinator starts a bounded shared LyricsRepository from native playback metadata, before the lyrics panel exists. Committed video identity gates results and availability. NativeActionModel transforms Music's actual Elements action-bar model: removes disabled Lyrics state/toast, supplies the normal native Music command only when missing, and moves the action after Like/Dislike. No personal button view/listener is added. Native presenter refresh uses its own committed response.

NativeLyricsHost prefers an existing Music Lyrics definition; if absent, it preserves the current Music Related palette/header contracts while replacing content/identity and requesting native mini-player snap. A transparent renderer attaches only to the active native Lyrics model's content FrameLayout. Old global title/decor installation and view overrides are disabled. Typed native contracts and six protobuf schema hashes guard application; runtime wire edits fail closed on unknown shapes.

The collapsed dock opener sits at the bottom. Expansion grows upward and places collapse above source/delay and action controls; opacity, glass, centered icons, persisted state and reduced motion remain supported. Browser/native-fixture/SDK checks are separate from pending phone acceptance.
